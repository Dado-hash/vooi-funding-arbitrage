# Changelog

Newest first. Dates are when the change was made.

- **2026-10-17**: `config.toml` is no longer tracked: the repo ships `config.example.toml` to copy and customize (like `.env.example`). `load_config` falls back to the example when `config.toml` is missing; tests always read the example.
- **2026-10-17**: Never open at a negative entry basis. New `[execution] min_entry_basis` (default 0, was a −20 bps warning): the `unfavorable entry basis` and `unfavorable basis at size` flags are now blocking, `arb propose open` refuses to create the proposal (`[basis] proposal NOT created`), and `arb execute` blocks the opening if the basis at mid or at size turned negative.
- **2026-10-16**: `arb scan` estimates costs and price impact at `[strategy].notional_per_strategy`; `[scan].notional_usd` removed, so the scan size can no longer drift from the traded size. `--notional` still overrides it.
- **2026-10-16**: Price impact in every decision. Costs use `estimate_slippage` on the entry and exit side of both legs at `notional_usd` (was entry only, doubled); `[scan] notional_usd` is now 100, equal to the trade size. New flags: `high price impact` (blocking, over `[execution] max_impact_bps` = 25 bps) and `unfavorable basis at size` (from the executable prices, `basis_at_size`). Pre-trade check blocks openings with high impact or a worse executable basis; closes are never blocked. Proposals and notify instructions show the impact. Monitor exit cost includes exit impact (`Exit now` in the daily summary). `arb portfolio` takes the capital from `get_accounts` when `--capital` is not given.
- **2026-10-16**: Daily summary built by code (`arb/summary.py`, `arb daily --send [--note]`, `--show`): Telegram HTML with status icons, positions, spreads, balances and the top 3 opportunities; the agent only adds an optional note. README shortened and redesigned (badges, features, diagram, agent table); details moved to `docs/strategy.md`, `docs/execution.md`, `docs/agents.md` and `docs/cli.md`.
- **2026-10-16**: Open-source preparation: all code, docs and messages translated to English; agent-neutral setup (`AGENTS.md` as the canonical instructions, `docs/cycle.md` as the monitoring procedure, `scripts/run-cycle.sh` for headless runs); `.claude/skills/cycle` replaces `ciclo`; MIT license; CI test workflow.
- **2026-10-16**: Automatic TP/SL protection (`arb/protection.py`, `tp_sl` and `tp_sl_liq_fraction` in `[execution]`): two shared price levels for both legs, at 70% of the estimated liquidation distance. In `execute` they are attached to the opening orders, verified after opening, and leftover TP/SL are cancelled after closes and safety closes. In `notify` they appear in the instructions. Instruction and proposal messages reformatted as Telegram HTML.
- **2026-10-16**: Position parser aligned with the real `get_positions` format. Without a mark price, notional and liquidation distance were `null`: the monitor never raised a margin alarm and close proposals had no reference price. The mark is now derived from entry price and uPnL. Tested against a real response.
- **2026-10-15**: First real use. Hyperliquid and Lighter connected with about $58 each (Hyperliquid in `unifiedAccount`, so spot USDC counts as margin). `[strategy]` sized to the capital: 1 strategy, $100 per leg. Balance parser aligned with the real `get_accounts` format. Telegram verified.
- **2026-10-15**: Capital check before opening proposals (`arb/capital.py`, `get_accounts`): margin per venue with a 10% buffer, suggested transfers between venues, no proposal when funds are missing. `arb execute` re-checks margin. New command `arb capital`, parameter `capital_buffer`.
- **2026-10-15**: Minimum target of 20% annual net return on capital, leverage included (`min_apr_on_capital`, `leverage` in `[strategy]`). New field `apr_on_capital` and flag `below target`. `arb portfolio` and the cycle skip pairs below the threshold. Replaces `min_net_horizon`.
- **2026-10-15**: `TRADING_MODE` in `.env` (`notify` by default: manual instructions with an Arbitrage Desk link; `execute`: approval and execution). Project command `/ciclo` with the loop procedure, `[strategy]` rules in config, `arb mode`, `arb daily`.
- **2026-10-15**: Project permission for `uv run arb *` (loop without confirmation prompts in Claude Code).
- **2026-10-15**: Telegram approval and MCP execution. New commands: `arb propose` (proposal with buttons), `arb tg wait`/`poll`, `arb execute` (`[execution]` limits, drift check, leg-by-leg execution with safety close), `arb proposals`. Default notional $1000 per leg ($500 margin × 2x).
- **2026-10-15**: No automatic execution: the analyst sends what to do on Telegram and the user executes on VOOI. New commands `arb plan` (order plan with rounded sizes and leg order) and `arb tg` (Telegram send).
- **2026-10-15**: Cross-venue basis in the model (expected and pessimistic) and price snapshots at each scan to estimate its historical mean. New command `arb portfolio` (capital, leverage, K strategies, liquidation risk).
- **2026-10-15**: Config set to Hyperliquid + Lighter, $100 per leg. New flags: `negative current spread`, `limited hours`, `same venue, different underlyings`.
- **2026-10-15**: Scan rewritten. Per-market history cached, pair spread computed locally: no more bias toward spikes. Real per-market fees from `get_quotes` (Aster 6 bps, not 3.5). Default history of 30 days with `mean_all`/`pos_all` and the `recent regime` flag. New command `arb venues`, flags `--dex` and `--days`. Removed `min_apr` and `max_candidates`, replaced by `min_hist_apr`. On-chain venue analysis: Hyperliquid + Lighter chosen.
- **2026-10-15**: First successful real scan (HTTP client with verified token, about 25s per scan). Ambiguous Aster assets resolved (previously 7 pairs on XAU/XAG/CL were discarded). Default horizon raised to 168h: at 72h almost no HL/Aster pair covers the taker costs.
- **2026-10-15**: First version. MCP HTTP client, scan funnel with duration and cost metrics, position monitor, SQLite journal, offline tests on real responses (CHIP aster/hyperliquid).
